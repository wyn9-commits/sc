ADVANCED DAX QUERIES V5
Covers all 12 question patterns. Supersedes V4.

WHAT CHANGED FROM V4 - READ THIS FIRST
  1. Site key contradiction RESOLVED. V4 and INSTRUCTIONS disagreed: one used
     [Site and Name], the other [Arch.Obj. ID]. They return DIFFERENT numbers.
     V5 uses 'CurMonData'[Arch.Obj. ID] everywhere. Run VALIDATION Q1 to confirm.
  2. Company code filter: V4 assumed CONTAINSSTRING. That also matches 16730,
     21673, etc. Run VALIDATION Q2 before trusting it. Both forms given below.
  3. NBV split into Current Month vs Current Year End. V4 treated them as one.
  4. Ownership: new canonical pattern using the reporting flag, not Property type.
  5. Vacancy fixed - V4's [#1 Occupant]="" never matches BLANK. Use ISBLANK.
  6. % of Site Cost no longer SUMmed - it is per-site and totalled to 1100%.
  7. Land/Building now returned in ONE query with counts. Separate queries merged
     by row position misattributed every region's value.
  8. Pattern 7 no longer text-searches site names as the primary method.


==========================================
VALIDATION - RUN THESE THREE FIRST, ONCE
==========================================
Do not deploy the rest of this library until these are answered.

Q1 - Which site key does the report actually use?
EVALUATE ROW("Distinct ArchObjID",DISTINCTCOUNT('CurMonData'[Arch.Obj. ID]),"Distinct SiteAndName",DISTINCTCOUNT('CurMonData'[Site and Name]),"Count_Site measure",CALCULATE([Count_Site]),"Count_Presentation",CALCULATE([Count_Presentation]))
-> Whichever raw count equals the built-in measure is the correct key. Use it everywhere.

Q2 - Is the company code filter exact-match or substring?
EVALUATE SUMMARIZECOLUMNS('CurMonData'[BE Company Code],"Rows",COUNTROWS('CurMonData'))
-> If codes are clean 4-digit values, use the EXACT form. If they are composite
   (e.g. "1673 - Entity Name"), use CONTAINSSTRING. Check whether any legitimate
   code CONTAINS 1673 or 7274 without BEING it - if so, CONTAINSSTRING is wrong.

Q3 - Does the reporting flag exist and how far does it diverge from Property type?
EVALUATE SUMMARIZECOLUMNS('CurMonData'[Property type],'CurMonData'[Property Type Reporting Flag],"Sites",DISTINCTCOUNT('CurMonData'[Arch.Obj. ID]),"Total Assets",SUM('CurMonData'[Total Assets]))
-> Expect Mixed and Excess to differ. This is why owned totals did not tie to the pivot.

==========================================
V4 used 'CurMonData'[#1 Occupant]="" which never matches BLANK in DAX. That is
why vacancy queries returned nothing. Use ISBLANK and check all occupant slots.

Vacant globally (no occupant in any slot):
EVALUATE CALCULATETABLE(SUMMARIZECOLUMNS('CurMonData'[Site and Name],'CurMonData'[City],'CurMonData'[Country Name],'CurMonData'[Main usage type],'CurMonData'[Property type]),'CurMonData'[Active/Terminated]="Active",FILTER(ALL('CurMonData'),(ISBLANK('CurMonData'[#1 Occupant]) || TRIM('CurMonData'[#1 Occupant])="") && (ISBLANK('CurMonData'[#2 Occupant]) || TRIM('CurMonData'[#2 Occupant])="")))

EVALUATE CALCULATETABLE(SUMMARIZECOLUMNS('CurMonData'[Site and Name],'CurMonData'[City]),'CurMonData'[Active/Terminated]="Active",'CurMonData'[Main usage type]="Office",FILTER(ALL('CurMonData'),ISBLANK('CurMonData'[#1 Occupant]) || TRIM('CurMonData'[#1 Occupant])=""))

CAVEAT: an empty occupant field means "no occupant recorded", which is not the
same as "vacant". True vacancy by space type is NOT tracked in this model. Say
this plainly rather than presenting unoccupied-field counts as vacancy.

PATTERN 12: TIME PERIOD QUESTIONS - READ THE LIMIT FIRST
==========================================
THE MODEL IS A CURRENT-MONTH SNAPSHOT. It cannot answer "which sites were active
during 2025". Term End filtering finds contracts EXPIRING in a period - that is
NOT the same as sites ACTIVE in that period. Do not present one as the other.

What Term End CAN answer - contracts expiring in a window:
EVALUATE CALCULATETABLE(SUMMARIZECOLUMNS('CurMonData'[Site and Name],'CurMonData'[Contract No and Name],'CurMonData'[Term End]),'CurMonData'[Active/Terminated]="Active",YEAR('CurMonData'[Term End])=2025)

Expiring in a specific month:
EVALUATE CALCULATETABLE(SUMMARIZECOLUMNS('CurMonData'[Site and Name],'CurMonData'[Contract No and Name],'CurMonData'[Term End]),'CurMonData'[Active/Terminated]="Active",YEAR('CurMonData'[Term End])=2025,MONTH('CurMonData'[Term End])=12)

Expired in the past 90 days:
EVALUATE CALCULATETABLE(SUMMARIZECOLUMNS('CurMonData'[Site and Name],'CurMonData'[Contract No and Name],'CurMonData'[Term End]),'CurMonData'[Term End]<TODAY(),'CurMonData'[Term End]>TODAY()-90)

Approximation for "had financial activity in 2025" - LABEL IT AN APPROXIMATION
every time it appears, not just once:
EVALUATE CALCULATETABLE(SUMMARIZECOLUMNS('CurMonData'[Region],"Sites",DISTINCTCOUNT('CurMonData'[Arch.Obj. ID])),'CurMonData'[Active/Terminated]="Active",FILTER(ALL('CurMonData'),SUM('CurMonData'[Total Prior Year Expenses])<>0))

==========================================
CRITICAL DAX RULES
==========================================
1.  SUM('CurMonData'[column]) for ALL CurMonData aggregation columns.
2.  CALCULATE([measure]) for KeyMeasures only: Count_Expired_Contract,
    Count_Contract, Count_Site, Value_NBV, Value_ROU, Value_Building, Value_Land,
    NBV_CY, NBV_NY, NBV_N2Y, NBV_N3Y, NBV_N4Y, NBV_TotalAsset, Count_Presentation,
    Count_Impaired, Count_Expired_Contract_No_SR, Count_ActContr_on_TermSite,
    Count_ActLeasedSite_No_Contract, TermSiteWithAcqVal.
3.  Billing File uses [Country]. CurMonData uses [Country Name]. NEVER MIX.
4.  Filter values are case-sensitive: "Australia" not "australia".
5.  Table names with spaces need quotes: 'Billing File', 'Need Attention'.
6.  Housing synonyms -> 'CurMonData'[Commercial / Housing]="Housing".
7.  Office / plant / warehouse types -> "Commercial".
8.  Time filters use YEAR(), MONTH(), DATE(), TODAY() with [Term End] - and
    Term End means contract expiry, NOT site active period.
9.  SITE COUNTS: always DISTINCTCOUNT('CurMonData'[Arch.Obj. ID]), never
    COUNTROWS/COUNT. One site spans many rows.
10. GLOBAL FILTER on every count and aggregate: exclude BE Company Code 1673 and
    7274. Missing this is why 7,066 sites was wrong. See PATTERN 0.
11. NEVER SUM a percentage column. Recompute with DIVIDE.
12. NEVER build a table from two queries merged by row position. One
    SUMMARIZECOLUMNS grouped by the same key, or join on the key explicitly.
13. TOTALS come from a separate aggregate query, never from adding printed rows.
14. NBV and ROU each have a current-month and a current-year form. Ask which.
15. Detail queries: cap at 200 rows and 10 columns. Wider queries have returned
    ConnectorRequestFailure while aggregates on the same filter succeeded.
